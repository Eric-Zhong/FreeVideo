# 02 · 技术栈与仓库布局

> 本篇梳理 FreeVideo 的技术选型与代码组织，为理解后续架构图提供“词典”。

## 1. 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 推理内核 | Python 3.12 + PyTorch + Triton | 模型前向由上游 `src` 提供，FreeVideo 做打补丁与自适应 |
| 注意力/量化内核 | SageAttention、Flash-Attn(fa2/fa4)、cuDNN、自研 Triton `int8_ops`/`fp8_gemm` | 按硬件能力自动选择 |
| 主机运行时 | ComfyUI（自定义节点 V3 API） | `WEB_DIRECTORY='./web'`，`comfy_entrypoint()` 注册路由 |
| 前端 | 原生 JavaScript (ES Modules)，**无打包/无构建** | 以 ComfyUI 扩展挂载，CSS 变量作用域化 |
| 桌面启动器 | PySide6-Essentials 6.11.2 + QtQuick/QML | 主启动器（Software 渲染，不占 GPU） |
| 引擎桌面工具 | Tkinter（`desktop.py`） | 独立的 Setup/Generate/Test/Tune 面板 |
| 打包 | PyInstaller（AppImage / .app / .exe） | 冻结分发包 |
| 包管理 | `uv`（python-build-standalone，版本锁定） | 隔离 venv，避免污染系统 Python |
| 模型分发 | HuggingFace / hf-mirror / ModelScope / 夸克离线包 | 校验 sha256 / git_blob，可断点续传 |
| 自更新 | 冻结源覆盖 + Ed25519 签名校验 | `freevideo_source_bootstrap.py` |

## 2. 代码规模（概览）

| 目录 | 体量 | 角色 |
|---|---|---|
| `freevideo_engine/` | ~410 个 `.py` + 资源 JSON | 推理引擎、内存/精度自适应、ComfyUI 集成、安装启动、Agent、LoRA、前端 REST 服务 |

## 3. `freevideo_engine/` 的模块主题分布

引擎目录按**职责前缀**高度自组织，便于按名定位：

- **生成与模型**：`generate.py`、`worker.py`、`runtime.py`、`blocks.py`、`attention.py`、`adaln*.py`、`head_chunk.py`、`conditioning.py`、`continuation*.py`、`decode*.py`、`encode*.py`、`latent_upscale.py`
- **内存/精度自适应**：`offload.py`、`streamed_weights.py`、`activation_staging.py`、`gpu_budget.py`、`capacity.py`、`compute_budget.py`、`fp8*.py`、`int8_ops.py`、`weight_only.py`、`kernel_capabilities.py`、`calibration.py`、`adaptive.py`、`capabilities.py`
- **ComfyUI 集成**：`comfy_*.py`（nodes/bridge/host/service/editor/chain/continuation/progress/launcher…）
- **安装/启动/打包**：`bootstrap.py`、`install*.py`、`install_schedule.py`、`install_disk.py`、`macos_*.py`、`linux_*.py`、`windows_*.py`、`launcher_*.py`、`modern_launcher.py`、`desktop*.py`、`offline_packages.py`、`network.py`、`download_*.py`
- **Agent**：`agent/`（REST/SSE API、MCP、会话、作业、白盒、导演等）
- **LoRA**：`lora_*.py`
- **链式长视频**：`chain_*.py`
- **诊断/健康**：`doctor.py`、`diagnostics*.py`、`diagnostic_*.py`、`feedback.py`

## 4. 两条执行路径

代码中存在**两套并行的生成实现**，对应不同后端：

- **CUDA 路径**（Windows / Linux）：`generate.py` → `worker.py` → `runtime.Engine` → 上游 `src.inference.render.generate_latents`。
- **macOS 路径**（Apple Silicon MPS）：`macos_*.py` 平行实现相同阶段（`macos_generate`、`macos_runtime`、`macos_vdn`、`macos_encoder`、`macos_decode`、`macos_memory` 等）。

两者对外暴露一致的“规划 → 条件化 → 采样 → 解码 → 媒体”阶段，差异仅在后端算子与内存策略。
