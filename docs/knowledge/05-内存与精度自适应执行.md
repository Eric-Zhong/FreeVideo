# 05 · 内存与精度自适应执行

> FreeVideo 的核心竞争力：**在 8GB 显存上跑 H3**。本篇拆解其“规划层 + 运行时层 + 精度抽象”三级自适应体系。

## 1. 三级自适应结构

```mermaid
flowchart TD
    P[规划层] -->|选放置方案| R[运行时层]
    R -->|执行并动态调整| K[精度抽象]
    K -->|选择内核| M[模型代码<br/>blocks/head_chunk/attention/adaln]

    subgraph P[规划层 - 离线/准入]
        P1[capabilities.py<br/>CPU 侧准入与估算]
        P2[calibration.py<br/>配对放置测量]
        P3[compute_budget.py<br/>按富余显存放大并行/分块]
        P4[policy.choose<br/>(generate.automatic_profile)]
    end
    subgraph R[运行时层 - 执行期]
        R1[offload.LayerOffloader<br/>顺序模块 offload + 预取]
```

## 2. 内存管理手段

### 权重的“按需驻留”
- **`LayerOffloader`**：顺序模块的边界 offloader，持有有界的 pinned-host 与 CUDA 缓冲；CPU 侧权重、pinning 预留（`_pin_reservation`、`live_pin_capacity`）与预取。Transformer 与 VAE 解码器都复用它。
- **`SafetensorLayers`**：对 safetensor 分片做内存映射 + 索引，仅把“驻留块”留在 GPU，非驻留层按需流式加载，由 `Engine.stream_weight_source` 与 `resident_blocks` 驱动。

### 激活的限界与暂存
- **`HeadReadouts`（`activation_staging.py`）**：连续的 D2H head-group 暂存 + 双缓冲 pinned CPU 投影分块，是 `attention_cpu_outputs` / `grouped_attention_outputs` 的底层机制。
- **`head_chunk.py`**：把 H3 激活按 head 分组限界（省显存的分片线性分支），可选 CPU 输出。
- **`blocks.py`**：融合 H3 块、丢弃已消费激活、复用分支输出；`chunked_ff` 平铺 FF 以限界峰值显存（Windows 无可扩展段时尤为关键）。

### 运行时动态调整
- **`LiveGPUBudget`（Windows）**：在 stage/step 空闲边界刷新分配器上限；压力下优先回收“可选权重”，仅限制未来分配。
- **`capacity.py`**：Windows 分配器准入与容量试跑，约束整进程分配器，使回收池块保持可复用而非被驱动分页到系统内存。
- **`compute_budget.spare_compute_trials`**：从实测富余显存**提出更大**的工作（head 并行、ff 分块、window 批、投影分块）——这是“放大”层而非“省内存”层。

### 预读与常驻
- `model_read_ahead`（编码期读视频模型）、`encoder_read_ahead` / `encoder_prewarm`（预热 OS 文件缓存页）、`decode_prefetch.DecoderReadAhead`（重叠采样尾步与解码器检查点读取）、`resident_models` / `resident_process`（空闲常驻）。

## 3. 数值精度与内核选择

精度按请求选择 `linear_compute ∈ {native-fp8, bf16-weight-only, int8}`：

| 文件 | 作用 |
|---|---|
| `fp8.py` | 官方 VDN FP8 权重与缩放粒度（`input_dtype`、`quantize_group`） |
| `fp8_ops.py` | 带 FP8 缩放的限界 head-chunk 投影（`quantize_fixed_scale`、`sliced_projection`） |
| `fp8_gemm.py` | FP8 GEMM 派发 |
| `int8_ops.py` | ConvRot int8（W8A8，int32 累加）投影，用于 CUDA（group-256 Hadamard 旋转） |
| `weight_only.py` | `WeightOnlyLinear`：仅权重量化（int8）线性，作为 FP8 替代 |
| `kernel_capabilities.py` | **执行回执式**后端选择（不 import CUDA 即可探测 `available_backends`、`readiness`、`fp8_implementation`） |
| `calibration.py` | 配对放置测量（`attention_cpu_outputs`、`fp8_ff_recompute`、`pinned_host_cache` 等）收集证据 |

- 注意力后端从 `cudnn / torch-flash / sage2 / fa2 / fa4` 中选择，由 `WindowAttention`（`attention.py`）安装到各混合注意力模块。
- 编码器侧：`encoder_precision.py` 以 **BF16** 运行 H3 文本编码器语言模型（而非 ComfyUI 默认的 FP32），减半每 token 显存并利用张量核心。

## 4. 平台差异（自适应落地）

- **CUDA（Win/Linux）**：int8（GeForce/RTX30）或 FP8（工作站/数据中心）；依赖 SageAttention、Flash-Attn、cuDNN。
- **macOS（MPS）**：统一内存，仅允许经校验的 int8 预处理模型（`macos_bootstrap.preflight` 拒绝 CUDA/Sage/重建缓存）。`macos_*.py` 平行实现各阶段、内存策略与解码分块。

## 5. 设计要点

- **规划与运行解耦**：规划层按硬件事实 + 实测证据定方案；运行时层在运行中动态收缩/扩张显存，优先回收可选常驻。
- **精度可替换、算术一致**：模型代码放置感知，同一份算术分区在 GPU / pinned host / 流式下保持一致，从而可在不重写模型的前提下切换精度与位置。
- **隔离与重试**：每个阶段在受监控子进程中运行，失败可从保留检查点 resume 解码或精修。
